# Contributing to Anti-REA

Спасибо за интерес к проекту. Anti-REA принимает исправления, новые defensive
probes, платформенные адаптеры и улучшения evidence protocol.

## Перед началом

1. Для существенного изменения сначала откройте issue с описанием угрозы,
   attacker tier и ожидаемого доказательства.
2. Не добавляйте реальные ключи, токены, закрытые артефакты или чужой код.
3. Offensive-примеры должны быть минимальными, воспроизводимыми и направленными
   на проверку защиты собственных или явно разрешённых продуктов.

## Локальная проверка

```bash
npm ci
npm test
npm audit --omit=dev
```

Изменение защитного механизма должно включать:

- отрицательный тест, демонстрирующий обход до исправления;
- положительный тест корректного production-пути;
- fail-closed поведение для отсутствующего или повреждённого evidence;
- обновление threat/breakout map и документации формата;
- честное описание остаточного обхода.

## Pull request

Делайте один логический change на PR. В описании укажите угрозу, границу доверия,
сценарий воспроизведения, результаты тестов и совместимость форматов. Автор
сохраняет авторские права на вклад и публикует его под AGPL-3.0-only.
