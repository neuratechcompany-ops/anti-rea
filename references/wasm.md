# WASM — обфускация

Бьёт по `inspect_wasm_artifact` (REA через WABT декодирует в WAT: секции,
импорты/экспорты, disasm, строки). WASM сам по себе уже «бинарный», но WAT
и строки в data-секции раскрывают логику.

## Что раскрывает WAT

- имена функций/импортов/экспортов (если не застриплены);
- строковые литералы в линейной памяти (data-сегменты);
- структуру вызовов.

## Контрмеры

### 1. Стрип имён (обязательно)
Сборка с вырезанием имён и debug-секций:
```bash
wasm-opt --strip-debug --strip-producers -O3 in.wasm -o out.wasm
# --strip-producers убирает компилятор/путь/версии (как -trimpath)
```

### 2. Обфускация строк
Литералы не класть в data-секцию plaintext — держать XOR/RC4 и расшифровывать в
рантайме (WASM-функция-дешифратор).

### 3. Обфускация control-flow / упаковка
- `wasm-opt -O3 ...` + кастомные пассы;
- коммерч./исслед. WASM-обфускаторы (opaque predicates, func-splitting);
- вынос чувствительных вычислений в JS+bytenode (javascript-electron.md) или
  в нативный .so, а WASM оставить как «тупой» вычислитель.

### 4. Эмбеддинг
Не отдавать `.wasm` отдельным файлом с читаемым путём — инлайнить
(base64/байты) в обфусцированный JS (см. javascript-electron.md).

Эмбеддинг меняет упаковку, но не обеспечивает конфиденциальность: браузер всё
равно декодирует модуль, а байты можно перехватить перед `WebAssembly.compile`
или `WebAssembly.instantiate`.

## Проверка через REA

```bash
# MCP: inspect_wasm_artifact -> summary/экспорты/WAT
#   -> имён нет, строки зашифрованы, WAT не раскрывает логику.
```

Критерий: WAT без имён функций и без читаемых строк в data-секции.

Для `COST_ONLY` логики этого недостаточно: owner заранее фиксирует
`wasm-structure` fingerprint reference WAT. Gate извлекает WAT из подписанного
raw analyzer output и сравнивает структуру после удаления имён, чисел, строк и
комментариев. Совпавшие opcode/control/section structure принудительно дают
recovery score 4 даже после переименования и замены литералов. Команда и
ограничения описаны в `framework-commands.md`.
